# 第一部分：系统架构设计方案

## 1. 总体架构设计理念
本系统遵循 **前后端分离** 的开发模式，采用标准的 B/S（Browser/Server）架构。设计遵循“高内聚、低耦合”原则，保证系统的可扩展性、易维护性和高性能。

## 2. 技术架构分层
系统主要分为四层：**表现层（Frontend）、接口层（API Gateway）、业务逻辑层（Service）和数据持久层（DAO）。**

*   **表现层 (Vue.js + Element UI)**
    *   负责页面渲染、用户交互及路由跳转。
    *   使用 Axios 进行异步 HTTP 请求，与后端交互。
    *   Vue Router 管理单页面应用（SPA）的路由。
    *   使用 Element UI 组件库快速构建响应式界面。

*   **接口/控制层 (Spring Boot Controller)**
    *   遵循 RESTful 风格设计 API。
    *   负责接收前端请求（JSON格式），进行参数校验（Validation）。
    *   集成了 Spring Security (或拦截器) 进行 JWT 身份认证与权限鉴权。

*   **业务逻辑层 (Spring Boot Service)**
    *   核心业务处理中心，处理如订单逻辑、库存扣减、支付状态流转等复杂业务。
    *   利用事务注解 (`@Transactional`) 确保数据的一致性（如：下单时同时生成订单和扣减库存）。

*   **数据持久层 (MyBatis / MyBatis-Plus)**
    *   负责与 MySQL 数据库交互。
    *   封装复杂的 SQL 查询，使用 Mapper 接口映射数据对象 (POJO)。

## 3. 部署架构 (基础设施)
*   **Web 服务器**: Nginx (可选，用于反向代理和静态资源托管)。
*   **应用服务器**: 内置 Tomcat (Spring Boot)。
*   **数据库**: MySQL 5.7/8.0 (存储业务数据)。
*   **文件存储**: 本地磁盘映射 或 阿里云OSS (存储商品图片、轮播图)。
*   **环境**: Docker 容器化部署 (可选)，支持 CI/CD 流水线。

# 第二部分：具体任务需求的业务流程说明

根据你提供的功能模块，以下是核心功能的详细业务流程设计：

## 一、前台用户系统业务流程

### 1. 用户注册与登录流程
*   **目的**: 确保用户身份合法，建立用户会话。
*   **流程**:
    1.  **注册**:
        *   用户在注册页输入账号、密码、确认密码、手机号。
        *   前端校验格式 -> 发送 POST 请求。
        *   后端查询数据库检查账号/手机号是否已存在。
        *   若不存在，密码加密（MD5/BCrypt）存入 `User` 表。
        *   返回注册成功提示。
    2.  **登录**:
        *   用户输入账号密码。
        *   后端比对加密密码。
        *   **成功**: 生成 JWT (JSON Web Token)，包含用户 ID 和角色信息，返回给前端。
        *   **前端处理**: 将 Token 存储在 localStorage 中，后续所有请求在 Header 中携带该 Token。

![用户注册和登录流程](..\..\3c电子商城平台\文档\图片\用户注册和登录流程.png)

### 2. 首页与商品搜索流程
*   **目的**: 展示商品，引导用户购买。
*   **流程**:
    1.  **首页加载**: 页面初始化时，并行请求“轮播图 API”和“推荐商品/分类 API”。
    2.  **渲染**: Vue 接收数据渲染 Banner 和商品卡片。
    3.  **搜索**:
        *   用户输入关键词 -> 点击搜索。
        *   后端执行模糊查询 (`LIKE %keyword%`)。
        *   返回符合条件的商品列表，前端分页展示。

![商品搜索流程](..\..\\3c电子商城平台\文档\图片\商品搜索流程.png)

### 3. 商品浏览与详情查看流程
*   **目的**: 展示商品详细参数，促进转化。
*   **流程**:
    1.  用户在列表页点击某商品。
    2.  页面跳转至 `Detail` 页，携带 `productId`。
    3.  根据 ID 请求后端获取：基础信息、价格、库存、多图、规格参数。
    4.  用户进行操作：**加入购物车** 或 **立即购买**。

![商品详情流程](..\..\3c电子商城平台\文档\图片\商品详情流程.png)

### 4. 购物车管理流程
*   **目的**: 临时存放商品，支持批量结算。
*   **流程**:
    1.  **添加**: 校验用户是否登录 -> 检查库存 -> 若购物车已存在该商品则数量+1，否则新增记录。
    2.  **查看**: 获取当前用户的购物车列表（包含商品图、名、单价、数量）。
    3.  **编辑**:
        *   **修改数量**: 点击 +/-，后端更新数量并重新计算小计。
        *   **删除**: 将商品移出购物车表。
    4.  **状态同步**: 勾选商品计算总价。

![购物车管理流程](..\..\3c电子商城平台\文档\图片\购物车管理流程.png)

### 5. 订单全流程（核心）
此部分逻辑最为复杂，包含结算、生成、支付、状态追踪。
*   **流程**:
    1.  **订单确认 (Pre-Order)**:
        *   用户在购物车点击“去结算”。
        *   进入确认页，选择收货地址（需调用地址管理接口），确认商品清单和总金额。
    2.  **提交订单 (Create Order)**:
        *   点击“提交订单”。
        *   **后端事务开启**:
            *   校验库存是否充足。
            *   在 `Order` 表创建主订单。
            *   在 `OrderItem` 表创建子订单（记录商品快照）。
            *   扣减对应商品库存。
            *   清空购物车中已购买的商品。
        *   返回订单号。
    3.  **支付 (Mock Payment)**:
        *   跳转支付页（展示支付宝/微信二维码，或模拟支付按钮）。
        *   用户点击支付 -> 后端校验金额。
        *   支付成功 -> 更新订单状态为 `已支付/待发货`。
    4.  **状态追踪**:
        *   用户在“我的订单”查看列表。
        *   后端根据订单状态（0:待支付, 1:待发货, 2:已发货, 3:已完成）返回数据。
        *   用户确认收货 -> 订单完成。

## 二、后台管理系统业务流程

### 1. 系统管理 (用户与菜单)
*   **用户管理**:
    *   管理员查看用户列表（分页）。
    *   管理员禁用违规用户（更新状态字段 `status = 0`）。
    *   重置用户密码。
*   **菜单管理 (RBAC)**:
    *   展示树形菜单结构。
    *   管理员新增菜单/按钮权限。
    *   **动态路由**: 用户登录时，根据角色请求后端，后端返回该角色有权的菜单列表，前端动态生成侧边栏。

### 2. 商品管理流程
*   **目的**: 维护商品库及营销资源。
*   **流程**:
    1.  **商品列表**: 分页展示，支持按分类筛选。
    2.  **新增/编辑商品**:
        *   填写名称、描述、价格、库存。
        *   **图片上传**: 前端上传文件 -> 后端接收并存入 OSS/本地 -> 返回 URL -> URL 存入数据库。
        *   **富文本编辑**: 录入商品详情 HTML。
    3.  **上下架**: 软删除或状态切换。
    4.  **轮播图管理**: 上传图片，关联跳转链接（如某商品ID），设置排序优先级。

### 3. 订单管理与统计流程
*   **目的**: 监控销售情况，处理发货。
*   **流程**:
    1.  **订单查询**: 管理员按时间段、订单号、用户ID筛选订单。
    2.  **订单处理**:
        *   查看“待发货”订单。
        *   点击“发货” -> 录入物流单号（可选） -> 更新状态为 `已发货`。
    3.  **统计报表**:
        *   后端聚合查询（Count/Sum）。
        *   计算：今日订单数、总销售额、热销商品Top10。
        *   前端使用 ECharts 绘制折线图或饼图。
    4.  **导出**: 后端使用 Apache POI 库生成 Excel 文件，供前端下载。
