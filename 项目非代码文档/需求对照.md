## 1) 按文档+图片核对：可能遗漏的任务需求

### A. 订单确认页必需的“地址管理”没在思维导图里显式出现

你的业务流程里订单确认页要“选择收货地址”，这意味着至少要有地址表与地址CRUD接口/页面，否则下单链路不完整。
**建议补充：**

- 前台：地址列表/新增/编辑/删除/设默认
- 后端：`/api/addresses` CRUD，订单创建时保存**地址快照**

### B. “发送订单信息给商家”需要落地方案（否则只是口头描述）

文档明确写了“支付完成后生成订单、发送一份订单信息给商家”。
**至少要选一种落地：**

- 简版：后台管理端“待发货订单”列表就是“商家收到订单”
- 加分版：邮件通知（SMTP）/站内通知（消息表）/WebSocket 提醒管理员

### C. 商品图片上传/存储与安全校验（后台商品管理必需）

文档里商品管理包含“图片、参数性能、轮播图更改”，并明确“文件存储可扩展到OSS或本地”。
**容易漏的关键点：**

- 上传接口（文件大小/类型白名单、路径隔离、重名处理）
- 图片URL存库 + 静态资源访问（Nginx或后端静态映射）
- 富文本HTML需要**XSS过滤/白名单**（否则安全风险）

### D. RBAC细到“按钮权限/动态路由”的实现任务

文档强调 RBAC，且要“菜单、按钮级权限管理”。
落地通常至少需要：

- 表：role / menu / role_menu（menu含 type=MENU/BUTTON、perm_code）
- 接口：登录后返回`menus`用于前端动态路由 + `perms`用于按钮级控制
- 前端：路由守卫 + 动态注入路由 + v-permission 指令/组件封装

### E. “性能优化与安全加固”是文档明确工作内容，但常被当成口号

文档写了：Redis缓存热点商品、前端资源加载优化、密码保密处理、关键操作二次确认、HTTPS。
对应到任务层面，建议至少补这些可验收点：

- 密码：BCrypt；登录失败次数限制（简单版：Redis计数）
- HTTPS：Docker部署时用 Nginx 终止 TLS（本地也可自签演示）
- 缓存：商品详情/首页推荐缓存 + 失效策略
- 关键操作：支付/删除要二次确认（前端）+ 权限校验（后端）

### F. 测试与交付：文档提到 Postman 接口测试，但你技术选型里没写“怎么跑”

文档明确“接口测试Postman确保API可用性”。
建议明确成可执行任务：

- Postman Collection + 环境变量（baseUrl/token）
- Newman 一键跑（CI里也能跑）

## 3) 可扩展需求（按“扩展难度/加分程度”给你一组可选项）

### 低成本高收益（强烈建议至少做2个）

- **收藏/加入心愿单**（favorite表）
- **浏览历史**（history表 or Redis）
- **商品对比**（前端本地缓存+简易对比页）
- **搜索筛选增强**：分类/价格区间/品牌（更符合3C品类“参数复杂”定位）

### 中等成本（做出来很像“真实电商”）

- **SKU/规格模型**（颜色/内存/版本；库存按SKU扣减）
- **优惠券/满减**（coupon + user_coupon；结算页计算）
- **评价系统**（comment + rating；订单完成后可评价）
- **订单超时取消**（待支付超过X分钟自动取消并回补库存：定时任务）

### 高难度加分项（看时间选做）

- **推荐系统**（简单版：基于浏览/购买的TopN；高级：行为序列）
- **秒杀/限时抢购**（Redis预减库存+限流+异步下单）
- **消息中心**（站内信、WebSocket实时提醒后台）

## 4) 优化建议（更贴合你现有技术栈）

### 后端（SpringBoot + 分层 + MySQL + Redis）

- **订单创建必须做幂等**：同一购物车/同一请求重复点击，避免重复下单（可用“幂等token”或order_no唯一约束）
- **库存扣减避免超卖**：SQL条件更新 `stock>=qty`（乐观扣减）+ 事务保证（你文档也强调事务一致性）
- **缓存策略**：Cache-Aside（读缓存→读库→回填；更新时删缓存），热点：商品详情/首页推荐（文档点名Redis缓存热点商品）
- **RBAC实现建议**：Spring Security（或拦截器JWT）+ 方法级注解 `@PreAuthorize("hasAuthority('xxx')")`，更清晰可演示
- **导出Excel**：建议异步生成/限制时间范围，避免大数据量卡死（你有“导出订单状态信息”需求）

### 前端（Vue3 + ElementPlus + Tailwind + axios + pinia）

- **ElementPlus + Tailwind 的分工**：
  - 后台管理：ElementPlus（表格/表单效率最高）
  - 前台商城：Tailwind（更灵活更“电商风”）
- **pinia分模块**：authStore / cartStore / userStore / adminStore（避免全局混乱）
- **axios拦截器统一处理**：token注入、401自动跳登录、错误码toast

### Docker部署（建议一步到位）

- `docker-compose.yml` 里至少包含：mysql、redis、backend、frontend、nginx（静态+反代+https可选），这也符合你/文档对Docker与前后端分离部署的描述。
